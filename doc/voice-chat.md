# 语音对话

轴伊的语音对话由三部分组成，结构参考 [Pipecat](https://github.com/pipecat-ai/pipecat)：

- **听**：本机判断说话轮次（Silero VAD + Smart Turn），本机识别语音（SenseVoice），语音不离开电脑。
- **想**：大模型生成回复并调用工具，默认使用百炼，也可以填写任意 OpenAI 兼容接口。
- **说**：本机 Qwen3-TTS 用轴伊的声音按句合成，边生成边播放。

```
麦克风 16 kHz ──▶ AEC3（Windows）──▶ Silero VAD ──▶ Smart Turn v3 ──┐
                                                                     │ 轮次结束
                                                SenseVoice（本机） ◀─┘
                                                        │ 用户文字
     工具执行 ◀──── tool_calls ◀──── 大模型流式输出 ◀────┘
        │ 结果                             │ 文字，按句切分
        └──────▶ 再次请求大模型            ▼
                          Qwen3-TTS（本机，每句一次）──▶ 24 kHz PCM ──▶ 扬声器
```

## 设置

在「对话 → 语音对话设置」中：

1. **下载本机语音模型**（识别约 237 MB、合成约 1.28 GB，只需一次）。下载后语音识别和轴伊的声音合成都在本机进行。
2. 填写北京地域的**百炼 API Key 和业务空间 ID**。用于网页搜索、查看桌面，以及未填写接口地址时的大模型。
3. **大模型**：默认 `qwen-plus`，可选或填写其他模型名。填写「大模型接口地址」后改用该 OpenAI 兼容接口（如 DeepSeek、本机 Ollama），
   并需填写该接口的 API Key；地址必须是 HTTPS，本机地址可用 HTTP，不能包含账号信息。
4. **麦克风和扬声器**：默认跟随系统默认设备，也可以单独选择。系统默认设备是远程桌面、串流或虚拟声卡时（例如 UU 远程、Steam 串流、VoiceMeeter），
   轴伊的回复会播放到那里，此时应在这里选择实际的扬声器。保存的是设备 ID（Windows 端点 ID / Core Audio 设备 UID），
   设备未连接时暂用系统默认，重新接入后自动恢复；插拔设备后可在设置中刷新设备列表。麦克风、扬声器和快捷键使用方式在「语音对话」卡片中选择，选择后立即保存。

两个 API Key 都只写不读，保存在 macOS 钥匙串或 Windows 凭据管理器中，只发送给对应的模型服务。保存设置后，下一次对话生效。

## 使用

- Mac 使用 Option，Windows 使用 Ctrl，在快捷键说明前的下拉框选择使用方式：
  - **按一下**（开关 · 全双工，默认）：按一次开启麦克风，再按一次关闭。开启期间由本机判断每句话何时说完，可连续多轮对话。
  - **按住**（半双工）：按下立即打断回复并开始录音，松开即发送。
  - 本机轮次检测模型无法加载时，开关模式退化为「按一下开始、再按一下发送」。
- 轴伊说话时检测到的语音先视为「试探」：本机每 0.5 秒识别一次已说内容，识别出至少 2 个字且与正在播放的回复不同时才打断，
  避免外放的回声把轴伊自己打断；整句只是回复的回声时直接丢弃。
- 打断时停止播放、取消大模型请求和本机合成，并取消未完成的工具；上下文只保留已经播出的句子（当前句按播放比例截取）。
- 宠物窗口不需要获得焦点；录音、思考、执行工具和回复状态显示在宠物附近。首次在 Mac 使用需要允许麦克风权限。
- 对话上下文保留最近 40 条消息，语音和文字聊天共用；麦克风关闭且空闲两分钟后断开并释放识别和合成模型占用的内存，上下文仍保留。
  修改语音对话设置或清空对话记录时重置上下文，重启 JPet 后重新开始。

## 文字聊天

「对话」页面底部的输入框可以直接给轴伊发消息：Enter 发送，Shift+Enter 换行，输入法选字时的 Enter 不会发送。

- 只需要 API Key 和业务空间 ID（或自定义大模型），不需要下载本机语音模型；文字聊天不加载识别和合成模型。
- 与语音使用同一个大模型、同一套工具和同一段上下文。文字消息的回复只显示不朗读，系统提示允许稍长的分段回复和完整链接。
- 回复逐字显示；工具调用以可展开的小卡片显示在回复之间。回复过程中可点击停止，已显示的文字保留在上下文中；
  直接发送新消息、或按快捷键说话，都会打断当前回复。
- 文字聊天期间按快捷键开启麦克风时，切换为语音连接并带上已有上下文。
- 回复超过 45 秒没有进展视为超时，提示重新发送。

## 本机识别与轮次检测

| 模型 | 用途 | 来源与许可 |
| --- | --- | --- |
| `silero_vad.onnx` | 语音活动检测：置信度 0.7，开始 0.2 s，停止 0.2 s | 随安装包，Silero VAD v5，MIT |
| `smart-turn-v3.2-cpu.onnx` | 判断一句话是否说完：最近 8 s，概率 > 0.5 视为说完，静音满 3 s 强制结束 | 随安装包，Pipecat Smart Turn，BSD-2-Clause |
| SenseVoice-Small int8 | 语音识别：普通话、粤语、英、日、韩，带标点与数字规整 | 按需下载，sherpa-onnx 导出（2025-09-09） |

- 模型下载到资料目录的 `models/sensevoice-int8-2025-09-09/`，逐个文件校验大小与 SHA-256，校验通过后写入 `verified` 标记。
  目前依次尝试 Hugging Face 与 hf-mirror.com；正式发布应改为 JPet 自己的 CDN。识别与合成模型在设置中作为一组下载、取消和删除。
- 三个模型共用随 JPet 分发的 sherpa-onnx 1.13.8 与 ONNX Runtime 1.28.2（均在运行时加载，最低 macOS 11）。
- 识别在独立线程中进行；识别器在第一轮识别时加载（约 1 秒），加载后峰值内存约 560 MB。

Apple M2 Max 上的识别实测（`voice_speech_probe`，识别使用 2 个线程）：

| 项目 | 结果 |
| --- | --- |
| 模型加载 | 约 1.0 s |
| 2 秒左右的指令 | 平均 51 ms，最长 85 ms（RTF 0.026） |
| 5–7 秒的真实录音（模型自带样例） | 100–150 ms |
| 15 条 JPet 指令 × Tingting（自然音色） | CER 3.4%，错误主要是「轴伊」→「周一」、「升」→「深」 |
| 同上 × 5 种系统音色 | CER 15.6%；Eddy、Grandpa、Sandy 等机械音色 19–24%，偏悲观 |
| 加白噪声 15 dB / 5 dB | CER 19.5% / 34.9% |

合成语音不能代表真人录音，结果只用于比较趋势；真实准确率还需要用真人录音验证。

## 本机语音合成

轴伊的声音由 [Qwen3-TTS](https://github.com/QwenLM/Qwen3-TTS) 12Hz 0.6B Base（Apache-2.0）在本机合成，
通过 [qwentts.cpp](https://github.com/ServeurpersoCom/qwentts.cpp)（MIT，GGML）运行：

| 项目 | 说明 |
| --- | --- |
| 模型 | `qwen-talker-0.6b-base-Q8_0.gguf`（947 MB）与 `qwen-tokenizer-12hz-Q8_0.gguf`（278 MB），来自 [Serveurperso/Qwen3-TTS-GGUF](https://huggingface.co/Serveurperso/Qwen3-TTS-GGUF) 固定版本 `b7ee2e8`，下载到 `models/qwen3-tts-0.6b-base-q8_0/` 并校验 SHA-256 |
| 音色 | 随安装包分发 `resources/models/joi-voice.json`：一段 8 秒轴伊录音提取的说话人向量和编码，加上该段文字，用于上下文克隆；不包含原始录音 |
| 运行库 | `libqwen.dylib` / `qwen.dll` 与 GGML，在运行时加载；由 [`build-scripts/ports/qwentts`](../build-scripts/ports/qwentts) 固定版本构建 |
| macOS | 单个 `libqwen.dylib`，GGML 静态链接，用 Metal 计算；需要 macOS 12 或更新版本 |
| Windows | GGML 以模块形式随 `qwen.dll` 分发：有 Vulkan 驱动时用显卡，否则按 CPU 指令集选择 CPU 版本；构建机需安装 Vulkan SDK 1.4.328.1（1.4.309 缺少 `SPIRV-Headers` 的 CMake 配置，无法构建） |

- 开始对话时在独立线程加载模型（约 0.5 秒）并合成一句预热语音（约 1.4 秒，用于构建 GPU 管线），与用户说话同时进行。
- 每句一次合成，流式输出；开头和结尾的静音被裁掉（分别保留 100 ms 与 200 ms），句内停顿保留。
  每句最多生成「每字 0.4 秒 + 2 秒」的音频，防止采样失控。
- 合成前把阿拉伯数字改写成中文读法（`1,250` → 一千二百五十、`30%` → 百分之三十、`2026年` → 二零二六年、`8:05` → 八点零五分），
  模型自身没有文本规整。
- 打断时取消当前句，取消在一帧（约 80 ms）内生效；被取消的句子不会再播出。
- 合成失败（模型损坏、内存不足等）时结束本次回复并提示「轴伊的声音暂时无法合成」；运行库无法加载或系统版本过低时开始对话前即提示。

Apple M2 Max（Metal）实测：每句开始出声约 0.2–0.4 秒，合成速度约为播放速度的 2.6 倍（RTF 0.38），
对话期间进程内存增加约 2.6 GB。M2 Max 的 CPU 上 RTF 约 1.05，无法实时，因此 CPU 合成只能作为没有显卡时的退路。

## 大模型与合成

- 默认请求 `https://{业务空间}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1/chat/completions`（流式，`enable_thinking=false`）。
  系统提示要求回复适合朗读、不用 Markdown，一般不超过三句话；单条回复最多 1024 token。
- 回复按中英文句末标点切句；第一句在 6 个字以上的逗号处即可切出，以缩短首句等待。链接和 Markdown 符号不朗读。
- 句子按顺序逐句合成，并据此记录每句的音频区间，用于计算打断时已播出的文字。合成速度快于播放，后一句的合成被前一句的播放时间掩盖。

## 对话记录

设置面板的「对话」页面（总览之后）以聊天形式按时间先后展示用户消息、轴伊回复和工具调用，打开时滚动到最新消息；语音消息标注「语音转写」。
工具调用显示名称、执行中/完成/失败/打断状态，可展开查看参数和结果摘要；点击「搜索」可搜索消息、工具名称、参数及错误信息，页面自动刷新，回复期间更快刷新。
同一轮中工具调用前后的回复分别显示，迟到的用户转写仍填入原来的用户消息，不会移动到下一条回复之后。
被打断或失败的回复会保留已收到的文字，转写失败时显示提示。

最近 200 条消息保存在本机 GameData 数据库中，重启后仍可查看。
旧版问答记录会自动转换成用户和轴伊的独立消息；旧版没有保存的工具调用无法补回。
不保存音频、截图、工具原始结果或凭据字段。工具参数与结果使用字段白名单，各自最多 4 KiB；
只保留必要设置值、成功状态、错误、提示、结果数量等摘要。清空游戏数据也会移除对话记录。
语音转写仅供参考，可能与实际说话内容存在差异；记录显示的是收到的回复文字，不代表所有文字都已播放。

工具执行状态显示在宠物旁边和语音设置中，设置页还会显示最近一次搜索的来源链接。

打开网页使用系统原生API，URL不作为命令执行。支持域名、IP、端口、查询参数与片段；
保留原始路径和查询参数，拒绝非网页协议、空域名、无效端口、控制字符与带账号密码的URL。

游戏操作复用面板使用的同一套本机游戏命令和费用校验，只有游戏接受操作才报告成功，随后只返回受影响的状态：任务操作返回当前任务和队列，扩容返回队列，属性/升星返回属性与价格，换装返回服装。状态读取失败不会把已成功的操作改报为失败，模型应单独查询而非重试操作。
查询不再提供完整状态入口；任务目录、历史和成就默认每页5项，最多10项，使用next_offset继续查询。
日常设置使用字段白名单和类型/范围校验，不读取或修改B站登录、Cookie、API Key、业务空间或大模型配置。轮盘程序/文件夹只能配置已存在的本机绝对路径，网页入口仅接受HTTP/HTTPS；配置不会自动启动程序或打开网页。窗口相关设置在主线程应用并保存，面板通过SSE同步更新；打断或退出会取消尚未应用的设置。

工具在独立线程顺序执行；每轮最多16次调用，同一条回复最多连续请求大模型8轮。
大模型的回复流结束后才执行其中的 `tool_calls`；取消或失败的回复不执行。所有调用的结果回传后再请求一次大模型续答，
续答前说的话与续答分别显示在对话记录中。
工具参数错误会返回 `invalid_arguments` 和合法字段/范围提示，模型可以修正参数并继续调用；错误不会关闭录音。
用户打断时取消排队中的工具，并为每个未完成的调用写入「已打断」结果，保证上下文中的调用都有结果；
已经执行的游戏操作可能已经生效，应查询实际状态，不能自动重复执行。关闭应用会等待工具线程结束后才销毁游戏数据。

查看桌面时，截图只在内存中压缩和传输，不保存到磁盘或日志。Mac首次使用需允许JPet录屏，
授权后重启应用再试。macOS 14及以后使用ScreenCaptureKit，11–13使用旧系统截图接口；
Windows使用GDI捕获。图片最长边不超过1920像素，JPEG不超过512KB。
截图发送到已配置的北京业务空间，通过 `qwen-vl-plus` 读取后，将观察文本交给大模型。
网页搜索使用同一API Key调用 `qwen-plus`；该业务空间还需允许访问这两个模型。
搜索使用独立的[联网搜索请求](https://help.aliyun.com/zh/model-studio/web-search)，与对话所用的大模型无关。
视觉请求格式参见[图像理解文档](https://help.aliyun.com/zh/model-studio/vision)。

| | `history`、`watch_later`、`favorites`、`followings` | 观看历史、稍后再看、收藏夹及其内容、关注列表 |

视频参数接受BV号、av号或视频链接；`mid` 为用户UID，可先用 `search` 的 `type=user` 查得。
列表默认每页5项、最多10项，结果按16 KB限制裁剪并提示翻页。返回中的 `url` 可交给 `open_url` 打开。
AI字幕取自B站AI总结接口返回的字幕，与请求的分P一一对应；B站没有为视频生成AI处理（纯音乐、无人声等）时，
总结和字幕都返回 `null` 与说明。UP主上传的CC字幕暂不读取：登录状态下的 `/x/player/wbi/v2` 会返回412，旧版 `/x/player/v2` 可能返回其他视频的AI字幕。

B站Cookie仅用于发往 `api.bilibili.com`、`api.live.bilibili.com` 和 `api.vc.bilibili.com` 的HTTPS请求，不交给大模型、不写入日志，也不跟随重定向。
未登录时公开查询仍可使用，账号相关功能会提示先在JPet中登录。
搜索服务限流、Cookie过期、录屏权限或模型权限不足时，工具返回可读错误，不能编造搜索或画面结果。
截图与搜索中的文字按外部数据处理，不作为额外操作指令。

## 回声消除（Windows）

Windows 录音和播放使用 WASAPI 共享模式，打开设置中选择的设备（未选择或未连接时用默认设备）；由系统音频引擎在设备格式与 16 kHz（录音）/24 kHz（播放）
单声道 16 bit PCM 之间转换。麦克风经过 WebRTC AudioProcessing（AEC3 回声消除、中等强度降噪、高通滤波）后再交给轮次检测和识别；
AEC3 的参考信号是 JPet 实际写入扬声器的回复 PCM（已乘音量），没有回复时写入静音，保证参考流连续。
麦克风开启期间播放流保持运行；麦克风关闭且回复播完 3 秒后释放播放设备，避免音频流阻止系统睡眠。
只消除轴伊自己的声音，其他程序播放的音乐、视频不在参考信号内。Mac 暂无回声消除，外放时只能依靠上面的回声文字比对。

- 设置环境变量 `JPET_VOICE_AEC=0` 后启动可关闭回声处理，用于对比原始录音。
- `jpet.log` 中 `[Voice] Capture wasapi ...` 与 `[Voice] Render wasapi ...` 记录实际打开的设备名称和延迟，以及 AEC 开关
  （Mac 为 `[Voice] Capture format ... device=` 与 `[Voice] Playback device=`）；麦克风开启时每 5 秒输出
  `[Voice] AEC ... reduction=…dB`，即处理前后麦克风电平差（包含降噪的作用）。
- 依赖 `webrtc-audio-processing` 2.1，由 [`build-scripts/ports`](../build-scripts/ports) 中的 vcpkg overlay port 构建为静态库；
  它要求 abseil 不低于 20240722 且仍提供 `absl::Nullable`，因此 `vcpkg.json` 将 abseil 固定为 20250127.1。
