# 游戏规则与存档

经验、属性、星星、任务、奖励、衣装和 50 个成就全部在本机计算和保存，不需要联网或登录。
规则位于 [`src/GameRules.cpp`](../src/GameRules.cpp)，运行与存档位于 [`src/GameManager.cpp`](../src/GameManager.cpp)。
面板、语音工具和桌宠点击都通过 `GameManager` 修改游戏，同一套校验和结算只有一份实现。

## 时间推进

- JPet 运行时每秒结算一次：每满 60 秒获得一次经验，任务按运行时间推进，完成后自动结算并启动队列中的下一个任务。
- 退出 JPet 时游戏暂停，离线时间不补算；重新打开后从暂停处继续，保留不足一分钟的经验进度和任务剩余时长。
- 两次结算的间隔超过 30 秒（电脑休眠、进程被挂起）时只计 30 秒。系统时间被调早时不推进，也不会卡住等待时间追回。
- 任务耗时以开始时的速度确定，成功率按完成时的属性确定。经验分钟与任务完成按发生的先后顺序结算。
- 加成（直播、动态、舰长、周一、生日）和轴芯等级来自 B 站状态检测，在结算完上一段时间后才生效。
- 自然日成就按 UTC+8 统计。

## 任务队列

任务队列基础容量为 2，解锁第 3、4、5、6 个位置分别消耗 1、2、5、10 颗星星，解锁后永久保留。
运行中的任务不占容量。队首任务成功率为 0 时队列暂停启动，提升属性、调整顺序或移除该任务后继续。
星星消耗后按剩余数量计算成长加成，超过新属性上限的部分按原规则转为经验，已获得的成就永久保留。

## 存档

存档以 JSON 保存在用户数据目录 GameData 数据库的 `game.state` 键，格式版本为 1。
发生可见变化（经验、属性、任务、队列、衣装、加成、新成就）时立即保存，否则至少每 15 秒保存一次进度，
正常退出时再保存一次；异常退出最多丢失 15 秒进度。存档无法读取时，原内容备份到 `game.state.invalid`，再按下文重新导入。

存档只在本机，不同电脑之间不同步，也不随 B 站账号切换。

## 从旧版本升级

首次启动本地版本、还没有 `game.state` 时，按以下顺序选择一份数据导入：

1. 云端版本最后一次收到的存档快照 `cloud.cache.<UID>.https://s.jpet.powerlive.io`，
   优先当前登录的 UID，其次是首次连接云端的 UID（`cloud.migration_uid`）。
2. 云端版本首次启动时备份的本机旧存档 `cloud.legacy_bootstrap`。
3. 更早版本分散保存的 `attr.*`、`task.*`、`task.queue`、`task.history` 和 `achievements.state`；全新安装得到默认属性。

导入保留属性、经验、星星、已解锁衣装、已扩容的队列位置、运行中的任务进度、队列、最近结算记录和成就进度。
快照不记录运行中的任务是否来自队列，导入后该任务完成时不计入「井井有条」成就。
只在其他电脑上推进过、未同步到这台电脑缓存的云端进度无法找回。导入不删除这些旧键。

## 验证

```sh
bash build-scripts/test_game_macos.sh
bash build-scripts/test_achievements_macos.sh
```

也可以在 CMake 配置时加 `-DJPET_BUILD_GAME_TESTS=ON`，通过 `ctest` 运行同样的 `game` 和 `achievements` 测试。
